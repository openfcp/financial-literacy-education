# 输出格式与交付物规范

所有角色的最终输出统一遵循本文件。标准结构直接对应《教育宣传岗子Agent能力与职责说明书》§8.7。

## 1. R1 体制机制管理者输出结构

```markdown
## [任务标题]

### 背景与依据
- 任务类型：[制定计划 / 起草制度 / 预算规划 / 答疑]
- 监管依据：[引用的监管文件 + 出处标注]
- 参考素材：[引用的内部文档 + 出处标注]

### [主体内容]
[按制度文件的标准章节结构或计划格式输出]

### 合规复核说明
- 已核对监管要求：[清单]
- 核对结果：[合规 / 存在待确认项，逐项列出]
- 证据留存提示：[本次交付物对应哪些证据，还需补哪些过程材料]

### 附件
- [生成的文件列表及说明]
```

年度计划必须同时给出文字版与表格版两个文件，并在"附件"中并列列出。

```markdown
## [活动名称]实施方案

### 活动概况
- 活动主题：[与监管通知逐字一致]
- 活动时间：

- 活动形式：[线上 / 线下 / 线上线下结合]
- 预计覆盖人次：

### 组织架构
- 领导小组：
- 责任分工：[牵头部门 + 配合部门]

### 活动安排
| 序号 | 活动内容 | 形式 | 时间 | 地点/渠道 | 负责人 | 预计覆盖人次 |
|------|----------|------|------|-----------|--------|-------------|

### 物料清单
| 物料名称 | 数量 | 用途 | 制作要求 | 配发对象 | 到位时间 |
|----------|------|------|----------|----------|----------|

### 舆情应对预案
- 可能风险点：
- 应对措施：
- 响应时限与升级路径：

### 数据报送要求
- 报送时间：
- 报送内容：
- 报送对象：
- 统计口径：

### 引用来源
[知识库文件名及具体条款]
```

活动安排表五要素：主题、时间、地点/渠道、负责人、预计覆盖人次。

## 3. R3 内容创作者输出结构

### 3.1 短视频脚本类

```markdown
## [主题]短视频脚本

### 创作背景
- 目标受众：
- 传播渠道：
- 时长要求：

### 故事情节
- **人物设定**：
- **场景描述**：
- **故事主线**：
- **冲突设置**：
- **教育意义**：

### 分镜脚本
| 镜头号 | 时长 | 画面内容 | 台词/旁白 | 配乐/音效 | 备注 |
|--------|------|----------|-----------|-----------|------|

### 制作建议
- 拍摄风格：
- 字幕与适老要求：
- 后期要求：
```

**故事情节必须先于分镜脚本输出**，顺序不可颠倒。

### 3.2 宣传文案 / 提示词类

```markdown
## [主题]宣传内容

### 创作要求
- 内容主题：
- 目标受众：
- 传播渠道：
- 形式要求：

### 核心信息
- 风险/知识点：
- 法规依据：[出处标注]

### 创作输出
[文案全文 / 提示词全文]

### 使用说明
[如何使用该内容 / 提示词；图像生成失败时的手动使用建议]
```

风险提示文案在"创作输出"中必须呈现三段：风险现象描述 + 后果说明 + 防范建议，并附标题、一句话版与适老版。

## 5. 交付物命名规范

| 交付物类型 | 命名规则 | 示例 |
|------------|----------|------|
| 年度计划（文字版） | `{年份}年度金融教育宣传工作计划.md` | `2026年度金融教育宣传工作计划.md` |
| 年度计划（表格版） | `{年份}年度金融教育工作计划表.xlsx` | `2026年度金融教育工作计划表.xlsx` |
| 管理办法 | `{制度名称}_v{版本号}.md` | `金融知识宣传教育管理办法_v1.0.md` |
| 活动方案 | `{活动名称}实施方案_{日期}.md` | `3·15宣传活动实施方案_20260315.md` |
| 活动总结 | `{活动名称}活动总结_{日期}.md` | `金融教育宣传月活动总结_20260930.md` |
| 短视频脚本 | `脚本_{主题}_{日期}.md` | `脚本_防范电信诈骗_20260714.md` |
| 宣传文案 | `文案_{主题}_{日期}.md` | `文案_非法集资风险提示_20260714.md` |
| 提示词 | `提示词_{用途}_{日期}.md` | `提示词_反洗钱宣传海报_20260714.md` |
| 评估报告 | `{周期}宣教效果评估报告.md` | `2026Q3季度宣教效果评估报告.md` |
| 数据台账 | `宣教工作数据统计台账_{周期}.xlsx` | `宣教工作数据统计台账_2026Q3.xlsx` |

日期统一 `YYYYMMDD`。主题/用途中不使用空格与斜杠，用下划线连接。

## 6. 输出质量六条

1. 面向消费者的内容通俗易懂，多用生活比喻，避免照搬法条。
2. 活动方案含五要素：主题、时间、地点/渠道、负责人、预计覆盖人次。
3. 脚本先故事后分镜。
4. 评估有数据有对比，含趋势与归因。
5. 输出语言与用户查询语言一致。
6. 所有输出基于知识库检索结果；无知识库支撑的内容须标注来源。

## 7. 引用与来源标注

| 场景 | 标注 |
|------|------|
| 机构知识库 | `[依据来源：<文件名> · <章节/条款>]` |
| 官方外部检索已核验 | `[依据来源：<发布机构> · <文件全称> · 官网核验]` |
| 外部检索未核验 | `[依据来源：外部检索，建议人工复核]` |
| 未核实的文号/条款号/数据 | `[待验证]` |
| 用户提供的数据 | `[数据来源：用户提供的 <文件名>]` |

文末统一附"需人工确认事项"清单（若有），列出待核实的依据、待补的数据、待定的报送口径。

## 8. 文件落盘约定

- 生成文件时先确认输出目录；未指定则放在当前会话工作区的交付目录下。
- `file_write` 只在二次合规复核通过后调用。
- 每个生成文件在回复中列出：文件名、路径、内容说明（对应输出协议的 `files_created`）。
- 同时提示用户还应留存哪些过程证据（照片、签到、发布截图、审批记录），以便应对监管评价。
