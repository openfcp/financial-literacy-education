# 知识库检索地图

本文件定义教育宣传岗履职所需的文档资源分类、元数据过滤标签、检索策略与引用标注规则。**所有角色的第一个动作都是查本文件确定检索范围，再执行检索。**

## 1. 六类文档地图

| 类别 | 具体文档 | 用途 | 核心内容 | 主要服务角色 |
|------|----------|------|----------|--------------|
| **制度计划类** | 金融知识宣传教育管理办法 | 明确工作机制、职责分工、运作流程 | 牵头/配合部门职责；计划制定→活动策划→组织实施→材料报送→总结评估全流程 | R1 |
| | 年度金融教育工作计划 | 规划全年目标与任务 | 年度目标、重点人群、量化指标（场次/人次/预算）、时间表 | R1 R2 R4 |
| | 年度消保培训计划 | 内部员工消保知识技能培训 | 培训对象、内容、考核方式 | R1 |
| **活动组织类** | 集中宣教活动实施方案 | 单次大型活动的具体安排 | 领导小组、分工、线上+线下安排、物料清单、舆情应对预案 | R2 |

| **法律法规库** | 金融教育相关法律法规 | 全系统共享法规基座 | 监管通知、处罚案例、权威解读 | 全部 |

## 2. 元数据过滤标签

检索时按下列维度组合过滤，**不要全库盲搜**：

| 标签 | 取值示例 | 说明 |
|------|----------|------|
| `doc_class` | 制度计划 / 活动组织 / 阵地建设 / 内容作品 / 评估分析 / 法律法规 | 一级分类 |
| `year` | 2024 / 2025 / 2026 | 计划、方案、报告强相关 |
| `role` | R1 / R2 / R3 / R4 | 按激活角色收窄 |
| `audience` | 老年人 / 年轻人 / 县域农村 / 新市民 / 在校学生 / 企业经营者 | 内容与阵地类 |
| `channel` | 网点 / 社区 / 校园 / 公众号 / 短视频 / 广播 / 短信 | 活动与渠道类 |
| `evidence_type` | 监管通知 / 内部制度 / 过程记录 / 成果数据 / 作品成品 | 证据链用途 |
| `effective_status` | 现行 / 已废止 / 待修订 | **引用前必查**，避免援引失效依据 |

## 3. 按任务类型的推荐检索组合

| 任务 | 首选标签组合 | 必取原文 | 常见遗漏 |
|------|--------------|----------|----------|
| 制定年度计划 | `doc_class=制度计划 + year=上一年度`、`doc_class=法律法规 + evidence_type=监管通知` | 上一年度计划、监管年度部署、消保评价中与教育宣传相关的评分维度 | 只看计划不看评价标准，导致指标对不上考评 |
| 起草/修订管理办法 | `doc_class=制度计划 + effective_status=现行`、`doc_class=法律法规` | 存量办法全文、牵头/配合部门职责、五环节流程 | 漏写"材料报送"环节 |
| 解读监管活动通知 | `doc_class=法律法规 + evidence_type=监管通知 + year=当年` | 通知全文（主题、时间节点、报送对象、报送格式） | **搞错主题或报送对象** |
| 制定活动实施方案 | 监管通知 + `doc_class=活动组织 + year=历年` | 历年方案、物料清单、总结数据表 | 漏舆情应对预案、漏数据报送要求 |
| 建设宣教专区 | `doc_class=阵地建设` | 专区标识/资料/设备/更新频率标准 | 只写硬件不写更新频率 |
| 创作风险提示 | `doc_class=内容作品 + evidence_type=作品成品`、`doc_class=法律法规` | 同类作品、典型案例、法规依据 | 照抄法条、缺"后果说明" |
| 创作短视频脚本 | `doc_class=内容作品 + audience=<目标人群>` | 同人群历史作品、知识点原文、真实案例 | 跳过故事情节直接写分镜 |
| 撰写评估报告 | `doc_class=评估分析 + year=本期/上期`、投诉关联分析 | 本期与上期台账、投诉数据、满意度调研 | 只罗列数据、无趋势对比与归因 |
| 编制案例集 | `doc_class=活动组织 + evidence_type=过程记录`、`doc_class=内容作品` | 活动亮点、作品成品、合作案例 | 只收活动不收作品 |

## 4. 检索策略

1. **先内后外**：内部制度通常严于监管底线且带本机构口径，优先级最高。
2. **监管原文以官方渠道为准**：涉及活动主题、时间节点、报送要求、法规时效时，联网核验国家金融监督管理总局及派出机构、中国人民银行、中国证监会、中国政府网、行业协会等官方发布的原文。
3. **文号与条款号一律以检索到的原文为准**。文件名可凭知识库命中写出，但**不得凭记忆补全文号、条款号、生效日期、评分分值**。无法核实就标 `[待验证]`。
4. **二次合规复核**：内容生成后，把关键结论（监管要求、指标口径、报送对象、活动主题）反向检索知识库交叉核对，排查遗漏、冲突表述、失效依据。
5. **检索无匹配**：放宽标签重试一次（先去掉 `year`，再去掉 `audience`/`channel`）；仍无结果则用外部检索并标注，同时明确告知用户"依据有限"，不得用常识补全。

## 5. 引用标注规则

| 场景 | 标注格式 |
|------|----------|
| 来自机构知识库 | `[依据来源：<文件名> · <章节/条款>]` |
| 来自官方外部检索且已核验 | `[依据来源：<发布机构> · <文件全称> · 官网核验]` |
| 来自外部检索未核验 | `[依据来源：外部检索，建议人工复核]` |
| 文号/条款号/数据未核实 | `[待验证]` + 在文末列出需核实项 |
| 用户提供的数据 | `[数据来源：用户提供的 <文件名>]` |
| 无来源支撑的判断 | 不得写成事实；如必须保留，改写为"建议进一步核实/确认" |

## 6. 证据留存意识

监管评价看的是"规划与投入—过程—成果—改进"的完整链条。生成任何交付物时同步考虑它能否作为证据：

- **规划与投入**：年度计划（双格式）、专项经费预算、管理办法。
- **过程**：实施方案、物料清单、活动照片、新闻稿、签到/参与记录、发布截图。
- **成果**：活动数据统计表、总结报告、原创作品库、媒体报道。
- **改进**：季度/年度评估报告、投诉关联分析、优秀案例集、制度修订记录。

在方案与总结类交付物中主动提示用户"需留存哪些过程材料"，避免活动做完却拿不出证据。
