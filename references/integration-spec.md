# 系统集成规格

本文件是给主 Agent / 集成方看的完整协议，定义调度条件、角色路由、编排逻辑、输入输出协议、工具权限、异常处理与上下文规则。Skill 内部的执行指引见 `SKILL.md`。

## 1. 主 Agent 调度条件

### 1.1 应调度给本子 Agent

| 调度条件 | 说明 | 示例 |
|----------|------|------|
| 涉及宣教制度/计划建设 | 编制、修订年度计划、管理办法等制度性文件 | "帮我制定2026年度金融教育宣传工作计划""起草一份宣教管理办法" |
| 涉及活动策划与组织 | 策划集中式宣教活动、建设宣教阵地、制定实施方案 | "策划一个3·15宣传活动方案""制定网点宣教专区建设标准" |
| 涉及内容创作 | 创作金融知识普及内容、视频脚本、提示词 | "帮我写一个防范电信诈骗的短视频脚本""生成一张反洗钱宣传海报的提示词" |
| 涉及效果评估与报告 | 输出统计报表、评估报告、案例分析 | "写一份季度宣教效果评估报告""统计一下今年的宣教覆盖数据" |
| 涉及宣教专业深度问题 | 需结合具体场景分析、多文档综合、创作性输出 | "针对老年人群体怎么设计金融教育内容""金融教育怎么融入贷款销售流程" |

### 1.2 主 Agent 自行处理（不调度）

- 简单常识性问答（"什么是金融教育宣传月""3·15是什么日子"）。
- 可通过单次知识库检索直接回答的法规条文查询（"金融教育宣传月是几月"）。
- 与教育宣传无关的其他消保领域问题。

## 2. 内部角色路由

| 意图特征 | 激活角色 | 判断关键词/模式 |
|----------|----------|-----------------|
| 制度/计划/机制 | R1 体制机制管理者 | 计划、制度、办法、管理办法、年度、预算、机制、体制、规划、工作流程 |
| 活动策划/阵地建设 | R2 活动组织策划者 | 策划、活动、方案、3·15、9月、宣传周、宣传月、五进入、专区、阵地、厅堂、微沙龙、物料 |
| 内容创作/翻译 | R3 内容创作者 | 脚本、文案、提示词、prompt、海报、视频、H5、漫画、风险提示、故事、创意 |
| 评估/统计/报告 | R4 效果评估者 | 评估、统计、报告、效果、覆盖率、数据、台账、案例、分析、投诉关联 |

**复合意图**：单次请求涉及多个角色时，按业务逻辑顺序串行激活。**无法判断角色时向用户追问确认**（给 2–3 个选项），不猜测。

## 3. 编排模式

采用**按需激活、串行编排**。

| 模式 | 适用场景 | 执行顺序 |
|------|----------|----------|
| 单角色模式 | 绝大多数场景 | 直接激活对应角色 |
| 策划-创作链 | 活动策划后需配套内容创作 | R2 → R3 |
| 策划-创作-评估链 | 完整活动周期 | R2 → R3 → R4 |
| 评估-机制链 | 评估发现问题后驱动制度优化 | R4 → R1 |
| 机制-策划链 | 制度制定后进入执行阶段 | R1 → R2 |

**链式执行规则**：

1. 前序角色的输出作为后序角色的输入上下文。
2. 每个角色独立执行其完整工作流，不跳步、不合并。
3. 链式总输出由最终角色汇总，包含全链路成果。
4. 用户可在任意环节中断并要求调整。
5. 某环节失败：已完成环节成果正常输出，失败环节跳过并说明原因。

## 4. 输入协议（主 Agent → 子 Agent）

```json
{
  "task_id": "string, 主Agent生成的唯一任务标识",
  "task_type": "enum: mechanism_management | event_planning | content_creation | effect_evaluation | composite",
  "user_query": "string, 用户原始问题（必填）",
  "attached_files": [
    {
      "filename": "string, 文件名",
      "file_path": "string, 文件路径",
      "file_type": "enum: document | image | spreadsheet | presentation | other",
      "text_content": "string, 已提取的文本内容（如有）"
    }
  ],
  "conversation_context": {
    "prior_messages": ["string, 相关历史对话摘要（最近3-5轮）"],
    "active_role_chain": ["string, 链式调用时已完成的角色列表"]
  },
  "knowledge_base_pre_hits": [
    {
      "source": "string, 知识库文件名",
      "chunk": "string, 匹配的原文片段",
      "relevance_score": "number, 相关度分数"
    }
  ]
}
```

字段说明：

- `task_type` 由主 Agent 预判，子 Agent 可自行修正。
- `attached_files` 为用户上传的参考文档、历史活动资料、数据文件。
- `knowledge_base_pre_hits` 为主 Agent 的预检索结果（可选）。即便已传入，子 Agent 仍需按自身任务补检索；预命中不能替代依据核验。

## 5. 输出协议（子 Agent → 主 Agent）

```json
{
  "task_id": "string, 回传主Agent的任务标识",
  "result_type": "enum: document | plan | script | prompt | report | advice | analysis | error",
  "role_executed": ["string, 实际执行的角色列表"],
  "content": {
    "summary": "string, 核心结论摘要（200字以内）",
    "detail": "string, 完整响应内容（Markdown格式）",
    "structured_data": "object | null, 结构化数据（活动数据统计、评估指标等）"
  },
  "references": [
    {
      "source": "string, 引用的知识库文件名",
      "section": "string, 引用的具体章节/条款",
      "relevance": "string, 引用目的说明"
    }
  ],
  "files_created": [
    {
      "filename": "string, 生成的文件名",
      "file_path": "string, 文件保存路径",
      "description": "string, 文件内容说明"
    }
  ],
  "follow_up_suggestions": ["string, 建议用户后续可执行的操作（最多3条）"],
  "confidence": "enum: high | medium | low, 输出可信度自评",
  "warnings": ["string, 需要用户注意的事项"]
}
```

**可信度自评口径**：`high` = 关键依据均可从知识库/官方原文核验且数据完整；`medium` = 部分依据来自外部检索或存在待确认项；`low` = 依据不足或数据缺失，输出中含占位/需求清单。凡标 `[待验证]` 的内容，`confidence` 不得为 `high`。

## 6. 工具权限矩阵

| 工具 | R1 | R2 | R3 | R4 |
|------|:--:|:--:|:--:|:--:|
| `knowledge_base_search` 本地向量知识库检索 | 是 | 是 | 是 | 是 |
| `web_search` 网络信息检索 | 是 | 是 | 是 | 是 |
| `file_write` 生成文档文件 | 是 | 是 | 是 | 是 |
| `image_generate` 图像生成 | 否 | 否 | 是 | 否 |
| `data_analysis` 数据分析与统计 | 否 | 否 | 否 | 是 |
| `llm_query` 大模型知识查询 | 是 | 是 | 是 | 是 |

- `image_generate` 仅 R3 可用，且必须在提示词生成之后调用。
- `data_analysis` 仅 R4 可用。
- `web_search` 全角色可用；R3 特别用于热点素材与行业案例，R1/R2 用于核验监管原文时效。

### 调用顺序约束

1. `knowledge_base_search` **必须优先调用**：任何角色执行业务逻辑前先取权威依据。
2. `web_search` 在知识库检索之后按需调用。
3. `image_generate` 仅在提示词生成后调用。
4. `file_write` 在内容生成并二次合规复核之后调用。

## 7. 异常处理

| 异常场景 | 处理策略 | 输出要求 |
|----------|----------|----------|
| 知识库检索无匹配结果 | 放宽检索条件重试一次；仍无结果用 `web_search`，标注 `[依据来源：外部检索，建议人工复核]` | 不得编造数据，明确告知检索结果有限 |
| 用户意图模糊无法判断角色 | 提出 2–3 个选项引导澄清 | "您的问题可能涉及以下方向，请确认：1. … 2. … 3. …" |
| 图像生成失败 | 输出提示词本身，告知可手动在其他工具中使用 | 附提示词全文与生成建议 |
| 上传文件无法解析 | 告知支持的文件格式，请求重新上传 | 列出支持的格式 |
| 任务超出能力边界 | 返回主 Agent 处理，附建议 | "该问题涉及XX领域，建议由XX子Agent处理。" |
| 数据不足无法生成评估报告 | 列出缺失数据项，告知需补充哪些数据 | 输出数据需求清单 |
| 链式执行中某环节失败 | 已完成环节结果正常输出，失败环节跳过并说明 | 输出已完成部分成果 + 失败说明 |

## 8. 上下文与记忆规则

### 8.1 无状态设计

- 子 Agent **不维护跨会话持久记忆**，每次调用独立执行。
- 所有必要上下文由主 Agent 通过 `conversation_context` 传入。
- 历史活动记录、制度版本、案例库等持久化数据存放在**知识库**中，不放在会话记忆里。

### 8.2 上下文传递边界

| 上下文类型 | 传递规则 |
|------------|----------|
| 用户原始问题 | 每次必传，完整传递 |
| 历史对话 | 主 Agent 传最近 3–5 轮相关对话摘要，非全量历史 |
| 前序角色输出 | 链式调用时，前序角色的 `content.detail` 原文作为后序输入上下文 |
| 知识库检索结果 | 主 Agent 预检索结果传入；子 Agent 自行补充检索的结果不回传主 Agent |
| 生成的文件 | 文件路径通过 `files_created` 回传主 Agent |

### 8.3 知识库作为持久化记忆

| 记忆类型 | 存储位置 | 更新机制 |
|----------|----------|----------|
| 宣教制度文件 | 知识库-制度计划类 | R1 通过 `file_write` 更新 |
| 活动方案与总结 | 知识库-活动组织类 | R2 沉淀 |
| 原创内容作品 | 知识库-内容作品类 | R3 沉淀 |
| 评估报告与数据 | 知识库-评估分析类 | R4 沉淀 |

> 沉淀前须经人工确认；本子 Agent 不擅自改写已生效制度或覆盖历史台账。
